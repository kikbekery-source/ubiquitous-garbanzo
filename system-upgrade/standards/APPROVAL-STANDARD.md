# 📏 บรรทัดฐานกลาง — Approve & Comment (ใช้กับทุกระบบ)
> ไฟล์กลางตามคำสั่งโค้ชกิ๊ก 1 ก.ค. 2026 · ให้ agent ทุกตัว (จาร์วิส กาโมร่า ฟอลคอน ฯลฯ) อ่านและทำตาม
> ให้เพิ่มลิงก์ไฟล์นี้เข้า `SYSTEM-RULES.md` ข้อ 8

---

## กฎข้อ 1 — ยังไม่ Approve = ยังไม่เสร็จ

- ทุกระบบ/ทุกหน้า/ทุกฟีเจอร์ ถือว่า **"ยังไม่สำเร็จ"** จนกว่าโค้ชจะกด Approve ว่าสำเร็จ 100%
- ระหว่างที่ยังไม่ Approve: **ปุ่มคอมเมนต์ปักหมุด (`ck-comment.js`) ต้องติดอยู่บนหน้านั้นเสมอ** ห้ามถอดออกเอง
- สถานะ Approve เก็บที่ `rooms.json` ฟิลด์ `approved: true/false` — คนเดียวที่เปลี่ยนเป็น `true` ได้คือโค้ช (หรือสั่งผ่าน agent ว่า "อนุมัติห้อง X")
- เมื่อ `approved: true` แล้วเท่านั้น จึงถอด widget คอมเมนต์ออกจากหน้านั้นได้

## กฎข้อ 2 — คอมเมนต์ของโค้ชคือใบสั่งงาน

- โค้ชคอมเมนต์ปักหมุดตรงจุดไหน = งานแก้ของจุดนั้น agent ผู้รับผิดชอบห้องต้องเข้ามาอ่านและแก้
- แก้เสร็จให้กดติ๊ก "✅ ทำเสร็จแล้ว" ที่หมุด (หมุดเปลี่ยนเป็นสีเขียว) — **ห้ามลบหมุดเอง** คนลบคือโค้ช
- คอมเมนต์ทั้งหมดเก็บที่ `/system/data/comments.json` — เห็นร่วมกันทุกคนทุกเครื่อง

## กฎข้อ 3 — เริ่มโปรเจกต์ใหม่ต้องถามก่อน

ทุกครั้งที่เริ่มโปรเจกต์/ห้องใหม่ agent **ต้องถามโค้ชก่อนเสมอ** ว่า:

> "โปรเจกต์นี้เกี่ยวข้องกับระบบหลังบ้านของโค้ชกิ๊กไหม?"

- ถ้าเกี่ยว → **ลงทะเบียนห้องทันที** ใน `rooms.json` (ผ่าน `rooms-api.php` action `update`)
- ถ้าไม่เกี่ยว → ทำงานปกติ ไม่ต้องลงทะเบียน

## กฎข้อ 4 — รายงานความคืบหน้าเข้าระบบทุกครั้ง

ทุกครั้งที่งานในห้องคืบหน้า (เริ่ม/ขยับเฟส/ติดปัญหา/เสร็จ) agent ต้องอัปเดตห้องตัวเอง:

```bash
curl -u kikkok:2222 -X POST https://coach-kik.com/system/api/rooms-api.php \
  -H "Content-Type: application/json" \
  -d '{"action":"update","room":{
    "id":"ชื่อห้อง-สั้นๆ",
    "name":"ชื่องานที่โค้ชอ่านเข้าใจ",
    "hero":"ฮีโร่ผู้รับผิดชอบ", "heroEmoji":"🦸", "heroImg":"/system/img/heroes/xxx.png",
    "status":"in-progress | blocked | done",
    "stage":"เฟส 2/4 — กำลังทำอะไร",
    "goal":"เป้าหมายของห้องนี้คืออะไร",
    "context":"บริบทที่คุยกัน/ตัดสินใจอะไรไปแล้ว",
    "blockers":"ติดอะไรอยู่ (ไม่ติด = -)",
    "needs":"ต้องการ API key/รหัส/ของจากโค้ชไหม (ไม่ต้อง = -)",
    "report":"/system/reports/ชื่อห้อง.html",
    "message":"ประโยคเดียวที่จะเด้งแจ้งเตือนหาโค้ช"
  }}'
```

- ฟิลด์ `report` ต้องชี้ไฟล์รายงานเต็มจริงๆ ในโฟลเดอร์ `/system/reports/` — สรุปให้โค้ชอ่านแล้วเข้าใจเลย: ทำอะไร ถึงไหน ติดอะไร ต้องการอะไร
- การอัปเดตจะทำให้เด้งป๊อปอัพแจ้งเตือน (พร้อมรูปฮีโร่ผู้รับผิดชอบ) — **ยกเว้น**ห้องที่โค้ชกด 🔕 ปิดเสียงไว้ จะเงียบจนกว่าโค้ชจะสั่งเปิดในห้องนั้นเอง
- API นี้อยู่หลัง login — agent ต้องใช้ `-u kikkok:2222` (ดู `auth/ACCESS.md`)

## กฎข้อ 5 — QA อัตโนมัติ (กาโมร่า)

- กาโมร่ารัน QA เป็นรอบอัตโนมัติบนเครื่องโค้ช (ตรวจ flow การใช้งานจริง ไม่ใช่แค่โค้ด)
- จบทุกรอบ ต้องรายงานผลผ่านกฎข้อ 4 — เจอบั๊ก = `status:"blocked"` + ใส่รายละเอียดใน report · ไม่เจอ = อัปเดตเงียบๆ (`message` สั้นๆ) ก็พอ
- บั๊กที่เจอให้เรียงความรุนแรง และบอกขั้นตอนทำซ้ำ (reproduce) ทุกตัว
